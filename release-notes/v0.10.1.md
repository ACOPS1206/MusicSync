## 한국어

Windows 출력이 늦게 들릴 수 있는 재생 시각 계산을 개선한 패치입니다. 실제 장치에서 시간차가 사라졌는지는 추가 비교가 필요합니다.

- Windows 출력: JavaSound에서 이벤트 기반 WASAPI 공유 모드로 전환했습니다.
- 고정 40 ms 추정값 대신 실제 버퍼 크기, 장치 위치·주파수·QPC 시각으로 재생 타임라인을 계산합니다.
- 시작 시 미리 채운 무음 및 underrun 무음을 프레임 번호에 반영합니다.
- 출력 시계를 100 ms마다 확인하며 큰 시각 변화 후 재정렬합니다.
- 출력 지연이 긴 클라이언트는 더 일찍 오디오를 예약합니다.
- Windows/Android/Linux 앱: **0.9.1 / Build 13** (desktop installer 0.9.1). Apple 앱은 0.8.0 (11), 웹은 0.10.0으로 유지합니다.

**Windows에서 다시 시험하기:** 기존 MusicSync를 완전히 종료한 뒤 이 릴리스의 `MusicSync-Windows.zip`을 새 폴더에 풀고 실행하세요. 화면에 **0.9.1 · Build 13**이 표시되는지 확인하세요. 우선 내장/유선 스피커로 테스트하세요. Bluetooth나 사운드 향상 기능에는 드라이버 시계로 보정되지 않는 추가 지연이 있을 수 있습니다. 호스트/클라이언트 역할, 상대 기기, 출력 장치, 대략적인 시간차와 로그를 기록하면 추가 진단에 도움이 됩니다.

시스템 오디오 모니터 캡처는 원래 Windows 소리를 지연시키지 않습니다. 이번 수정은 MusicSync 자체의 로컬/클라이언트 출력에 적용됩니다. 실제 스피커 정렬 및 드라이버별 정확도는 CI에서 검증할 수 없습니다.

iOS IPA는 unsigned이며 macOS는 Developer ID 서명·공증 없는 ad-hoc 서명입니다. Android APK는 CI debug 키로 서명합니다. 웹은 Node.js 22+/OpenSSL과 개인 LAN CA 신뢰 설정이 필요합니다. 기존 릴리스와 동일한 설치 제한이 적용됩니다. MIT 라이선스, 체크섬과 모든 플랫폼의 배포 파일을 포함합니다.

## English

Windows output timing patch. Playback now uses an event-driven native WASAPI shared-mode renderer instead of JavaSound's mixer position and a fixed 40 ms estimate. Hardware clock frequency/position and QPC sample time are mapped to the JVM monotonic timeline, accounting for startup and underrun silence. The shared scheduler checks output clocks every 100 ms, re-anchors large discontinuities and schedules further ahead for high-latency routes.

Ports are **0.9.1 / build 13** (desktop package 0.9.1); Apple stays 0.8.0 build 11 and web 0.10.0. Close the old Windows app, extract this release's portable ZIP into a new folder, and confirm the UI version before retesting. Start with wired/internal speakers. Physical acoustic synchronization and unreported Bluetooth/enhancement latency still require device testing; this patch is not a guarantee of measured speaker alignment. Original system audio in monitor-capture mode remains undelayed.

Unsigned iOS, ad-hoc/non-notarized macOS, CI debug-signed Android, and the web private-CA setup requirements remain unchanged. MIT licensing and SHA-256 checksums are included.
