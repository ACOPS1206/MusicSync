## 한국어

페어링을 앱 재시작 후 기억하지 않도록 변경했습니다.

- macOS/iOS/Windows/Linux/Android: 페어링 비밀, 호스트 공개키 고정값, 기기 제어 권한은 현재 앱 실행 세션의 메모리에만 보관합니다.
- 어느 한쪽 앱을 종료하고 다시 실행하면 8자리 코드를 다시 확인하고 호스트에서 승인해야 합니다. 앱이 실행 중인 동안의 자동 재연결은 기존 TLS 인증을 유지합니다.
- 기존 디스크/Keychain/Android 설정의 페어링 기록은 새 버전 첫 실행 시 삭제하도록 이관했습니다. 오래된 기록을 인증에 사용하지 않습니다.
- 호스트 TLS 개인키·인증서는 페어링 기록과 별도로 유지합니다. 호스트 인증서가 사라졌다면 클라이언트를 재시작한 뒤 다시 페어링하세요. 같은 실행 세션에서 호스트 키가 바뀌면 자동 신뢰하지 않으며, 기존 페어링을 지우거나 클라이언트를 재시작해야 합니다.
- 웹 게이트웨이 페어링은 메모리에만 유지하고 기존 pairings.json을 삭제합니다. 게이트웨이 재시작 또는 브라우저 페이지 새로고침 후에는 재승인합니다. HTTPS 인증서/개인 CA 신뢰 설정은 그대로 유지합니다.
- TLS 1.3 암호화, 독립 계산한 코드 비교, 클라이언트 확인 및 호스트 승인 절차는 유지합니다. v0.10.2의 Android 안정성·Windows 출력 수정도 포함합니다.

**앱 버전:** Apple **0.8.2 · Build 13**, Android/Windows/Linux **0.9.3 · Build 15**, 웹 **0.10.3**. 양쪽 앱을 함께 갱신하세요. 최신 앱은 오래된 상대의 저장된 페어링 증명에도 다시 승인을 요구합니다.

iOS IPA는 unsigned, macOS는 ad-hoc 서명·미공증, Android APK는 CI debug 키 서명입니다. Android 업데이트 서명이 달라 설치가 거부되면 기존 앱 제거 후 설치가 필요할 수 있습니다. MIT 라이선스 및 SHA256SUMS.txt를 포함합니다.

## English

Pairing is now scoped to the running app session on all native platforms. Secrets, pins and device permissions remain only in memory; restarting either endpoint requires code comparison and Host approval again. In-process automatic reconnection retains TLS-bound authentication and key pinning. Legacy persistent pairing entries are removed and never trusted.

Host TLS identity remains separately persistent. If it is lost, restart the Client and approve the new pairing. A Host key change during an active app session still stops automatic trust. Web gateway records are memory-only; gateway restart or browser reload requires approval. HTTPS certificates and private-CA trust are unchanged.

Apple: 0.8.2 build 13; ports: 0.9.3 build 15; web: 0.10.3. Update both endpoints. TLS 1.3, code confirmation, Host approval, and v0.10.2 audio/transport fixes remain in place. Signing/installation limitations are unchanged.
